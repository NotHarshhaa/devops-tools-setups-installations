## What you will learn

- **Git** — install it, configure your identity, understand the staging area and use a branching
  model that scales with your team.
- **GitHub CLI** — authenticate with `gh`, review pull requests and cut releases from the terminal.
- **GitLab CLI** — authenticate with `glab` and work with merge requests, pipelines and projects.

## Workflow recommendations

1. Commit small, focused changes with messages that explain the *why*
2. Rebase local work before opening a pull request
3. Protect the default branch and require reviews
4. Use signed commits or tags for releases
5. Configure a credential helper or SSH keys once — never store tokens in plain text
