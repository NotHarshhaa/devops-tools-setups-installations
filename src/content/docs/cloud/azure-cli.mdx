The Azure CLI (`az`) is Microsoft's cross-platform tool for managing Azure resources. It
runs on Linux, macOS and Windows, in a container, or directly in Azure Cloud Shell.

<Callout title="Versions used in this guide">
  Azure CLI **2.91.0** · the official `packages.microsoft.com` apt and dnf repositories ·
  Bicep (`az bicep`) ships with the CLI · managed identity and federated credentials for
  automation
</Callout>

## System Requirements

- A 64-bit operating system: Linux, macOS or Windows
- Python 3.10 or newer on Linux (the Windows MSI and the Docker image bundle their own)
- An Azure subscription and a way to authenticate
- The CLI installs to `/opt/az` on Ubuntu and Debian, and `/lib64/az` on RHEL-family
  distributions

  <TabsContent value="ubuntu">
    ### Ubuntu / Debian (apt)

    ```bash
    # Prerequisites
    sudo apt update
    sudo apt install -y ca-certificates curl apt-transport-https lsb-release gnupg

    # Install the Microsoft signing key in a keyring
    sudo mkdir -p -m 755 /etc/apt/keyrings
    curl -sL https://packages.microsoft.com/keys/microsoft.asc \
      | sudo gpg --dearmor -o /etc/apt/keyrings/microsoft.gpg
    sudo chmod a+r /etc/apt/keyrings/microsoft.gpg

    # Add the Azure CLI repository
    AZ_REPO=$(lsb_release -cs)
    echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/microsoft.gpg] https://packages.microsoft.com/repos/azure-cli/ $AZ_REPO main" \
      | sudo tee /etc/apt/sources.list.d/azure-cli.list

    # Install
    sudo apt update
    sudo apt install -y azure-cli

    # Verify
    az version
    ```
  </TabsContent>

  <TabsContent value="rpm">
    ### RHEL / CentOS / Rocky / Alma (dnf)

    ```bash
    # Import the Microsoft signing key
    sudo rpm --import https://packages.microsoft.com/keys/microsoft.asc

    # Add the Azure CLI repository
    sudo dnf install -y dnf-plugins-core
    sudo dnf config-manager --add-repo https://packages.microsoft.com/yumrepos/azure-cli
    sudo dnf config-manager --set-enabled azure-cli

    # Install
    sudo dnf install -y azure-cli

    az version
    ```
  </TabsContent>

  <TabsContent value="fedora">
    ### Fedora (dnf)

    ```bash
    sudo rpm --import https://packages.microsoft.com/keys/microsoft.asc

    sudo dnf config-manager --add-repo https://packages.microsoft.com/yumrepos/azure-cli
    ```


    ### Windows

    ```powershell

    # Microsoft Installer (MSI)

    # Chocolatey
    choco install azure-cli
    ```

  <TabsContent value="docker">
    ### Docker

    ```bash
    docker run --rm -it \
      -v $HOME/.azure:/root/.azure \
      mcr.microsoft.com/azure-cli:2.91.0 \
      az version
    ```

    For an interactive session, mount the config directory and set the terminal type:
    ```bash
    docker run --rm -it \
      -v $HOME/.azure:/root/.azure \
      -e TERM=xterm \
      mcr.microsoft.com/azure-cli:2.91.0 \
      bash
    ```

## Verifying the Installation

```bash
# Version, core version and installed extensions
az version

# List the installed extensions
az extension list

# The CLI comes with Bicep — no separate install needed
az bicep version
```

## Authentication

### Interactive login

```bash
# Opens a browser
az login

# For a headless machine, print a code and open it on any device
az login --use-device-code

# Log in to a specific tenant
az login --tenant <tenant-id>

# See what you are signed in to
az account show
```

### Service principal with a certificate (recommended for automation)

```bash
# Create the app registration
az ad sp create-for-rbac \
  --name my-app \
  --role Contributor \
  --scopes /subscriptions/<subscription-id>
```

```bash
# Add a certificate credential and export the public key
az ad sp credential reset \
  --id <app-id> \
  --append \
  --cert "$(openssl req -new -x509 -nodes -days 365 -out /dev/null -subj '/CN=azure-cli' | openssl x509 -pubkey -noout | openssl pkey -pubin -outform der | base64 -w0)"

# Log in with the certificate
az login --service-principal \
  --username <app-id> \
  --tenant <tenant-id> \
  --cert @cert.pem
```

### Managed identity and federated credentials

On any Azure resource that has a managed identity, the CLI picks it up automatically —
no secrets at all:

```bash
# Inside a VM, AKS pod or App Service with a managed identity
az account show

# On GitHub Actions, use the OIDC federation
az login --service-principal \
  --username <app-id> \
  --tenant <tenant-id> \
  --federated-token "$AZURE_FEDERATED_TOKEN"
```

```yaml
# GitHub Actions
permissions:
  id-token: write
  contents: read
steps:
  - uses: azure/login@v2
    with:
      client-id: ${{ secrets.AZURE_CLIENT_ID }}
      tenant-id: ${{ secrets.AZURE_TENANT_ID }}
      subscription-id: ${{ secrets.AZURE_SUBSCRIPTION_ID }}
```

## Working with Subscriptions

```bash
# List the subscriptions you can see
az account list --output table

# Switch the active subscription
az account set --subscription "My Subscription"

# List every subscription in a directory
az account list --all --output table
```

## Configuration

```bash
# Set the defaults you always want
az configure --defaults output=json location=westus2

# See the current defaults
az configure --list-defaults

# Export them for another environment
az configure --defaults output=table group=myResourceGroup
```

```json
// ~/.azure/config
{
  "defaults": {
    "group": "myResourceGroup",
    "location": "westus2",
    "vm": {
      "image": "UbuntuLTS",
      "size": "Standard_DS2_v2"
    }
  }
}
```

## Everyday Commands

### Resource groups

```bash
az group create --name myResourceGroup --location westus2 --tags Environment=Production
az group list --output table
az group delete --name myResourceGroup --yes
```

### Virtual machines

```bash
# Create a VM
az vm create \
  --resource-group myResourceGroup \
  --name myVM \
  --image UbuntuLTS \
  --admin-username azureuser \
  --generate-ssh-keys

# List, start and stop
az vm list --output table
az vm start --resource-group myResourceGroup --name myVM
az vm stop --resource-group myResourceGroup --name myVM

# Open a shell (Cloud Shell)
az vm ssh --resource-group myResourceGroup --name myVM
```

### Deployments

```bash
# Deploy an ARM template
az deployment group create \
  --resource-group myResourceGroup \
  --template-file template.json \
  --parameters parameters.json

# Deploy Bicep — az bicep is included with the CLI
az bicep build main.bicep --outfile main.json
az deployment group create --resource-group myResourceGroup --template-file main.json

# Deploy straight from a Bicep file
az deployment group create \
  --resource-group myResourceGroup \
  --template-file main.bicep \
  --parameters env=prod
```

## Extensions

```bash
# List the extensions in the index
az extension list-available --output table

# Install one
az extension add --name aks-preview

# Update or remove
az extension update --name aks-preview
az extension remove --name aks-preview
```

## Upgrading

```bash
# Check the current version
az version

# Upgrade the CLI
az upgrade

# If the automatic upgrade is blocked, install the latest package
sudo apt update && sudo apt install --only-upgrade azure-cli
```

## Troubleshooting

<Accordion type="single">
  <AccordionItem value="issue-1">
    <AccordionTrigger>
      az: command not found
    </AccordionTrigger>
    <AccordionContent>
      The CLI installs to `/opt/az` and symlinks into `/usr/bin`. If the symlink is
      missing:
      ```bash
      which az
      ls /opt/az/bin/az
      export PATH="$PATH:/opt/az/bin"
      ```
      On macOS with Homebrew, run `brew link azure-cli`.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-2">
    <AccordionTrigger>
      Authentication errors
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # Clear the cached credentials
      az logout

      # Log in again
      az login --use-device-code

      # See which account and subscription are active
      az account show
      ```
      If the tenant requires MFA, the device-code flow is the most reliable way to
      authenticate from a terminal.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-3">
    <AccordionTrigger>
      "Please run 'az login' to setup account" or a subscription error
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      az account list
      az account set --subscription "<subscription-id>"
      ```
      A service principal only sees the subscriptions its role assignment covers — check
      with `az role assignment list --assignee <object-id>`.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-4">
    <AccordionTrigger>
      An extension fails to install or update
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # List what is installed
      az extension list

      # Remove the broken one and install it again
      az extension remove --name <extension-name>
      az extension add --name <extension-name>

      # Extensions must match the CLI's major version
      az extension list-available | grep <extension-name>
      ```
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-5">
    <AccordionTrigger>
      The CLI is slow
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # Table output is what is slow — it has to collect every column
      az group list --output table
      az group list --output json --query "[].{name:name,location:location}"
      ```
      Use `--query` to reduce the amount of data the CLI has to fetch and format.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-6">
    <AccordionTrigger>
      "az bicep: command not found"
    </AccordionTrigger>
    <AccordionContent>
      Bicep is bundled with the CLI in 2.91.0. If it is missing, install it separately:
      ```bash
      az bicep install
      ```
    </AccordionContent>
  </AccordionItem>
</Accordion>

## Best Practices

1. **Use managed identity or federated credentials** in CI — never a client secret.
2. **Use a certificate credential** for service principals that run outside Azure.
3. **Scope role assignments** to the resource group, not the whole subscription.
4. **Set defaults with `az configure`** so every command uses the same output format.
5. **Use `--query` with `--output json`** in scripts instead of parsing human-readable output.
6. **Pin the CLI version** in your CI image and upgrade it deliberately.
7. **Keep the CLI and the extensions** on matching versions.
8. **Use Bicep** (`az bicep build`) for infrastructure instead of hand-written JSON.
