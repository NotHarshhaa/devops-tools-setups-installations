The Google Cloud CLI (`gcloud`) is the command-line tool for Google Cloud. It manages
resources, configures authentication and installs the companion tools you need.

<Callout title="Versions used in this guide">
  Google Cloud CLI **590.0.0** · the `google-cloud-cli` apt and rpm packages ·
  **Python 3.10 – 3.15** supported · `gcloud storage` replaces the legacy `gsutil` ·
  components are installed as **separate packages** when you use apt or rpm
</Callout>

<Callout title="Components work differently with package managers">
  `gcloud components install` only works with a tarball or Homebrew installation. When you
  install with `apt` or `yum`, the component manager is disabled and you install
  components as packages such as `google-cloud-cli-kubectl` or
  `google-cloud-cli-gke-gcloud-auth-plugin` instead.
</Callout>

## System Requirements

- A 64-bit operating system: Linux, macOS or Windows
- Python 3.10 to 3.15 (the Linux x86_64 package bundles its own interpreter)
- A Google Cloud project and an account with access to it
- `curl`, `tar` and `unzip` for the manual installation

  <TabsContent value="ubuntu">
    ### Ubuntu / Debian (apt)

    ```bash
    # Install the signing key in a keyring
    sudo mkdir -p -m 755 /usr/share/keyrings
    curl https://packages.cloud.google.com/apt/doc/apt-key.gpg \
      | sudo gpg --dearmor -o /usr/share/keyrings/cloud.google.gpg
    sudo chmod a+r /usr/share/keyrings/cloud.google.gpg

    # Add the Cloud SDK repository
    echo "deb [signed-by=/usr/share/keyrings/cloud.google.gpg] https://packages.cloud.google.com/apt cloud-sdk main" \
      | sudo tee -a /etc/apt/sources.list.d/google-cloud-sdk.list

    # Install
    sudo apt update
    sudo apt install -y google-cloud-cli

    # Initialize
    gcloud init

    # Verify
    gcloud --version
    ```

    <Callout title="Do not use apt-key">
      `apt-key` is deprecated and removed on Ubuntu 22.04+ and Debian 12. The command
      above writes the key to a keyring and references it with `signed-by`, which works on
      every current distribution.
    </Callout>
  </TabsContent>

  <TabsContent value="rpm">

    # Add the Cloud SDK repository
    sudo tee -a /etc/yum.repos.d/google-cloud-sdk.repo << EOM

    name=Google Cloud CLI

## Verifying the Installation

```bash
# Version and components
gcloud --version

# The active configuration
gcloud info

# The projects you can reach
gcloud projects list
```

## Authentication

```bash
# Interactive login — opens a browser
gcloud init

# Log in again without re-running init
gcloud auth login

# Use a device code on a headless machine
gcloud auth login --no-launch-browser
```

### Application Default Credentials

Every Google Cloud client library and every tool that talks to the API uses ADC:

```bash
# Create the ADC file for local development
gcloud auth application-default login

# Check what ADC currently points at
gcloud auth application-default print-access-token
```

### Service accounts and impersonation

```bash
# Create a service account
gcloud iam service-accounts create my-sa \
  --display-name "My Service Account"

# Grant it the least privilege it needs
gcloud projects add-iam-policy-binding PROJECT_ID \
  --member="serviceAccount:my-sa@PROJECT_ID.iam.gserviceaccount.com" \
  --role="roles/viewer"

# Impersonate it instead of downloading a key
gcloud auth application-default login \
  --impersonate-service-account=my-sa@PROJECT_ID.iam.gserviceaccount.com
```

<Callout title="Avoid service account key files">
  Long-lived JSON keys end up in environment variables, CI logs and repositories.
  Prefer workload identity federation or service account impersonation — both give
  short-lived credentials with no key to leak.
</Callout>

## Configurations

A configuration is a named set of properties (account, project, region, zone):

```bash
# Create one
gcloud config configurations create my-config

# List them
gcloud config configurations list

# Switch to one
gcloud config configurations activate my-config

# See the active properties
gcloud config list

# Set properties
gcloud config set project PROJECT_ID
gcloud config set compute/region europe-west4
gcloud config set compute/zone europe-west4-a
```

```yaml
# ~/.config/gcloud/configurations/config_my-config
[core]
account = user@example.com
project = my-project-id
disable_usage_reporting = True

[compute]
zone = europe-west4-a
region = europe-west4
```

## Everyday Commands

### Compute Engine

```bash
# List instances
gcloud compute instances list

# Create an instance
gcloud compute instances create my-instance \
  --machine-type=e2-medium \
  --image-family=ubuntu-2404-lts-amd64 \
  --image-project=ubuntu-os-cloud \
  --zone=europe-west4-a

# SSH into it
gcloud compute ssh my-instance --zone=europe-west4-a

# Stop and delete
gcloud compute instances stop my-instance --zone=europe-west4-a
gcloud compute instances delete my-instance --zone=europe-west4-a
```

### Cloud Storage

```bash
# Use gcloud storage — gsutil is the legacy tool
gcloud storage buckets create gs://my-bucket --location=EU

# List buckets
gcloud storage ls

# Copy files
gcloud storage cp ./file.txt gs://my-bucket/
gcloud storage rs --recursive ./local-dir gs://my-bucket/dir/

# IAM on a bucket
gcloud storage buckets add-iam-policy-binding gs://my-bucket \
  --member="user:john@example.com" \
  --role="roles/storage.objectViewer"
```

### Kubernetes Engine

```bash
# Install the auth plugin for GKE (a separate package when installed with apt)
sudo apt install -y google-cloud-cli-gke-gcloud-auth-plugin

# Get the credentials for a cluster
gcloud container clusters get-credentials my-cluster --region=europe-west4

# Then use kubectl
kubectl get nodes
```

## Components and Extra Tools

```bash
# With a tarball or Homebrew installation you can manage components
gcloud components list
gcloud components install kubectl
gcloud components update
```

```bash
# With apt or rpm, install the matching package instead
sudo apt install -y google-cloud-cli-kubectl
sudo apt install -y google-cloud-cli-gke-gcloud-auth-plugin
sudo apt install -y google-cloud-cli-docker-credential-gcr
```

## Upgrading

```bash
# With apt or rpm
sudo apt update && sudo apt install --only-upgrade google-cloud-cli

# With a tarball installation
gcloud components update
```

## Troubleshooting

<Accordion type="single">
  <AccordionItem value="issue-1">
    <AccordionTrigger>
      gcloud: command not found
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # Check where it is
      which gcloud

      # Add the SDK to your PATH
      export PATH="$PATH:$(/usr/lib/google-cloud-sdk/bin)"
      echo 'export PATH="$PATH:/usr/lib/google-cloud-sdk/bin"' >> ~/.bashrc
      ```
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-2">
    <AccordionTrigger>
      "The component manager is disabled for this installation"
    </AccordionTrigger>
    <AccordionContent>
      You installed the CLI with `apt` or `yum`, where components are packages:
      ```bash
      sudo apt install -y google-cloud-cli-kubectl
      ```
      Use `gcloud components install` only with a tarball or Homebrew installation.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-3">
    <AccordionTrigger>
      Authentication errors
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # Which account is active?
      gcloud auth list

      # Log in again
      gcloud auth login

      # Drop the cached credentials and start over
      gcloud auth revoke --all
      gcloud auth application-default login
      ```
      If the account needs MFA, `gcloud auth login` prompts for the second factor.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-4">
    <AccordionTrigger>
      "The project was not found" or a quota error
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # Which project is selected?
      gcloud config list
      gcloud config set project PROJECT_ID

      # Do you have access to it?
      gcloud projects get-iam-policy PROJECT_ID
      ```
      The CLI also needs the `serviceusage.services.use` permission on the target service —
      ask an owner to grant `roles/serviceusage.serviceUsageConsumer`.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-5">
    <AccordionTrigger>
      gcloud is slow or hangs
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # See the API calls
      gcloud compute instances list --verbosity=debug

      # Skip the usage report prompt and the update check
      gcloud config set core/disable_usage_reporting true
      gcloud config set core/disable_prompts true
      ```
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-6">
    <AccordionTrigger>
      Permission denied on a specific command
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # Check the effective permissions of the active account
      gcloud projects get-iam-policy PROJECT_ID \
        --flatten="bindings[].members" \
        --filter="bindings.members:user:my-user@example.com"

      # Check the active service account, if any
      gcloud auth list --filter=status:ACTIVE --format="value(account)"
      ```
    </AccordionContent>
  </AccordionItem>
</Accordion>

## Best Practices

1. **Use named configurations** per project or environment and activate them explicitly.
2. **Use impersonation or workload identity federation** instead of service account keys.
3. **Grant the narrowest role** that works — start from `roles/viewer` and add on.
4. **Use `gcloud storage`**, not the legacy `gsutil`.
5. **Always pass `--project` and `--zone` explicitly in scripts** so the command does not
   depend on the active configuration.
6. **Use `--format=json` and `--filter`** to get machine-readable output.
7. **Pin the CLI version** in CI images.
8. **Keep `gcloud config set core/disable_usage_reporting true`** in automation so
   non-interactive runs never block on a prompt.
