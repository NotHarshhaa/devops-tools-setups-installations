The Elastic Stack is three products that work together: **Elasticsearch** stores and
searches your data, **Logstash** ingests and transforms it, and **Kibana** visualises it.

<Callout title="Versions used in this guide">
  Elasticsearch **9.5.5** · Logstash **9.5.5** · Kibana **9.5.5** · the
  `artifacts.elastic.co/packages/9.x` repositories · security auto-configuration with TLS
  and an enrollment token
</Callout>

<Callout title="Check the licence before you deploy">
  Since 8.16 the default Elastic distribution is licensed under **AGPL v3** (with
  source-available options for some features). If you need a permissive licence, use
  **OpenSearch** — it is API-compatible with the parts of Elasticsearch this guide
  covers and is licensed under Apache 2.0.
</Callout>

## System Requirements

- 64-bit Linux, macOS or Windows (Linux is the supported production platform)
- **At least 4 GB RAM** for Elasticsearch, 8 GB or more for a production node
- Java is **bundled** with the packages — you do not need to install a JDK
- `vm.max_map_count` set to `262144` (Elasticsearch refuses to start otherwise)
- Ports 9200 (Elasticsearch), 9300 (transport), 5044 (Logstash Beats input), 9600
  (Logstash monitoring), 5601 (Kibana)
- 20 GB free disk for the data volume

  <TabsContent value="ubuntu">
    ### Ubuntu / Debian (apt)

    ```bash
    # 1. Import the Elastic signing key
    wget -qO - https://artifacts.elastic.co/GPG-KEY-elasticsearch \
      | sudo gpg --dearmor -o /usr/share/keyrings/elasticsearch-keyring.gpg

    # 2. Add the 9.x repository
    echo "deb [signed-by=/usr/share/keyrings/elasticsearch-keyring.gpg] https://artifacts.elastic.co/packages/9.x/apt stable main" \
      | sudo tee /etc/apt/sources.list.d/elastic-9.x.list

    # 3. Install the stack
    sudo apt-get update
    sudo apt-get install -y elasticsearch logstash kibana

    # 4. Raise the memory map limit
    sudo sysctl -w vm.max_map_count=262144
    echo "vm.max_map_count=262144" | sudo tee /etc/sysctl.d/99-elastic.conf
    sudo sysctl --system

    # 5. Start the services
    sudo systemctl daemon-reload
    sudo systemctl enable --now elasticsearch
    sudo systemctl enable --now kibana
    sudo systemctl enable --now logstash
    ```

    <Callout title="apt-key is gone">
      The old `apt-key add` command was removed in Debian 12 and Ubuntu 24.04. The key
      now goes into `/usr/share/keyrings/` and the repository references it with
      `signed-by=`.
    </Callout>
  </TabsContent>

## Security Setup

Elasticsearch 9 configures security automatically on first start: it generates TLS
certificates for the transport and HTTP layers, creates an enrollment token for Kibana and
enables the `elastic` superuser.

### 1. Set the `elastic` password

Because the service runs under systemd, the password is not printed in the terminal. Set
it with the reset tool:

```bash
cd /usr/share/elasticsearch
sudo -u elasticsearch bin/elasticsearch-reset-password -u elastic
```

```bash
# Store it for the rest of the session
export ELASTIC_PASSWORD='the-password-you-just-set'
```

### 2. Verify Elasticsearch

```bash
curl --cacert /etc/elasticsearch/certs/http_ca.crt \
  -u "elastic:$ELASTIC_PASSWORD" https://localhost:9200
```

```json
{
  "name": "Cp8oag6",
  "cluster_name": "elasticsearch",
  "version": { "number": "9.5.5" },
  "tagline": "You Know, for Search"
}
```

### 3. Connect Kibana

```bash
# Get the enrollment token from Elasticsearch
cd /usr/share/elasticsearch
sudo -u elasticsearch bin/elasticsearch-create-enrollment-token --ca-fingerprint /etc/elasticsearch/certs/http_ca.crt
```

```bash
# On the Kibana host, start Kibana with the token
sudo systemctl stop kibana
sudo /usr/share/kibana/bin/kibana \
  --elasticsearch.hosts=https://localhost:9200 \
  --elasticsearch.ssl.certificateAuthorities=/etc/kibana/config/http_ca.crt \
  --elasticsearch.username=kibana_system \
  --elasticsearch.password=<enrollment-token> \
  --encryption.key="$(openssl rand -base64 32)" \
  &
```

The token is valid for 30 minutes. Kibana writes the security configuration to
`/etc/kibana/kibana.yml`, so this only has to be done once.

## Logstash Pipeline

Create `/etc/logstash/pipeline/logstash.conf`:

```ruby
input {
  beats {
    port => 5044
  }
}

filter {
  if [type] == "syslog" {
    grok {
      match => { "message" => "%{SYSLOGTIMESTAMP:syslog_timestamp} %{SYSLOGHOST:syslog_hostname} %{DATA:syslog_program}(?:\[%{POSINT:syslog_pid}\])?: %{GREEDYDATA:syslog_message}" }
      tag_on_failure => ["_syslog_parse_failure"]
    }
    date {
      match => [ "syslog_timestamp", "MMM  d HH:mm:ss", "ISO8601" ]
    }
  }
}

output {
  elasticsearch {
    hosts => ["https://localhost:9200"]
    user => "elastic"
    password => "${ELASTIC_PASSWORD}"
    ssl_certificate => "/etc/elasticsearch/certs/http_ca.crt"
    index => "logs-%{+YYYY.MM.dd}"
  }

  stdout {
    codec => rubydebug
  }
}
```

```bash
# Validate the pipeline before reloading
sudo /usr/share/logstash/bin/logstash --path.settings /etc/logstash -t

# Reload
sudo systemctl reload logstash
sudo journalctl -u logstash -f
```

3. **Stack Management → Index Patterns** → create `logs-*`
4. **Discover** → search your data

## Multi-Node Cluster

For a real cluster you need at least three master-eligible nodes:

```bash
# On the first node
sudo tee -a /etc/elasticsearch/elasticsearch.yml > /dev/null <<'EOF'
cluster.name: my-cluster
node.name: node-1
network.host: 0.0.0.0
transport.host: 0.0.0.0
discovery.seed.hosts: ["10.0.0.11", "10.0.0.12", "10.0.0.13"]
cluster.initial_master_nodes: ["node-1", "node-2", "node-3"]
EOF
```

```bash
# On the other nodes, enrol them with a token (valid for 30 minutes)
sudo -u elasticsearch /usr/share/elasticsearch/bin/elasticsearch-create-enrollment-token -s node
sudo -u elasticsearch /usr/share/elasticsearch/bin/elasticsearch-reconfigure-node --enrollment-token <token>
```

<Callout title="Remove cluster.initial_master_nodes after bootstrapping">
  Leaving the bootstrap configuration in place means a restarted cluster can
  accidentally form a second cluster. Remove it once the nodes have joined.
</Callout>

## Troubleshooting

<Accordion type="single">
  <AccordionItem value="issue-1">
    <AccordionTrigger>
      Elasticsearch will not start
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      sudo journalctl -u elasticsearch -n 100 --no-pager
      ```
      The most common cause is the memory map limit:
      ```bash
      sysctl vm.max_map_count
      sudo sysctl -w vm.max_map_count=262144
      echo "vm.max_map_count=262144" | sudo tee /etc/sysctl.d/99-elastic.conf
      ```
      The second most common cause is running out of memory — the JVM heap is capped at
      50% of the available RAM.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-2">
    <AccordionTrigger>
      Certificate errors when connecting to Elasticsearch
    </AccordionTrigger>
    <AccordionContent>
      Elasticsearch generates its own CA on first start. Point the client at it:
      ```bash
      curl --cacert /etc/elasticsearch/certs/http_ca.crt -u elastic:$ELASTIC_PASSWORD https://localhost:9200
      ```
      ```yaml
      # In Logstash
      elasticsearch {
        hosts => ["https://localhost:9200"]
        ssl_certificate => "/etc/elasticsearch/certs/http_ca.crt"
      }
      ```
      The fingerprint is printed in the Elasticsearch log at startup.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-3">
    <AccordionTrigger>
      Kibana will not start
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      sudo journalctl -u kibana -n 100 --no-pager
      ```
      The usual reasons are an expired enrollment token (they last 30 minutes) or a
      missing `elasticsearch.password` in `kibana.yml`. Generate a fresh token:
      ```bash
      cd /usr/share/kibana
      sudo -u kibana bin/kibana-encryption-key generate
      ```
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-4">
    <AccordionTrigger>
      Logstash does not start or the pipeline fails
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # Test the configuration
      sudo /usr/share/logstash/bin/logstash --path.settings /etc/logstash -t

      # Read the logs
      sudo journalctl -u logstash -f
      ```
      A syntax error in the pipeline stops Logstash from starting at all.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-5">
    <AccordionTrigger>
      Indices are not created / data does not appear
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # List the indices
      curl -s --cacert /etc/elasticsearch/certs/http_ca.crt \
        -u "elastic:$ELASTIC_PASSWORD" https://localhost:9200/_cat/indices?v

      # Check the Logstash output
      sudo journalctl -u logstash | grep -i error
      ```
      If `action.auto_create_index` was disabled, create the index pattern explicitly
      with `action.auto_create_index: .monitoring*,.watches,.triggered_watches,.watcher-history*,.ml*`.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-6">
    <AccordionTrigger>
      The cluster is red or has unassigned shards
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      curl -s --cacert /etc/elasticsearch/certs/http_ca.crt \
        -u "elastic:$ELASTIC_PASSWORD" \
        "https://localhost:9200/_cluster/health?pretty"
      ```
      A yellow cluster means the replicas are not allocated (usually a single-node
      cluster). A red cluster means a primary shard is missing — check the node logs and
      the disk space.
    </AccordionContent>
  </AccordionItem>
</Accordion>

## Best Practices

1. **Enable the security features** — TLS, the `elastic` superuser and role-based access
   are on by default in 9.x. Never disable them in production.
2. **Use an ILM policy** so old indices are deleted automatically:
   ```bash
   curl -s --cacert /etc/elasticsearch/certs/http_ca.crt -u "elastic:$ELASTIC_PASSWORD" \
     -X PUT "https://localhost:9200/_ilm/policy/logs_policy" -H 'Content-Type: application/json' -d '{
       "policy": {
         "phases": {
           "hot": { "actions": { "rollover": { "max_primary_shard_size": "50gb" } } },
           "delete": { "min_age": "30d", "actions": { "delete": {} } }
         }
       }
     }'
   ```
3. **Take snapshots** to a shared repository — a snapshot repository is not a backup
   unless it is off-cluster.
4. **Ship logs with Filebeat or Elastic Agent** rather than running Logstash on every
   host.
5. **Never put credentials in `logstash.conf`** — use a keystore or environment
   variables.
6. **Pin the version** across all three components; Elasticsearch, Kibana and Logstash
   must be on compatible versions.
7. **Monitor the JVM heap** — a heap over 75% means the node is under pressure.
