Nagios Core is the original open-source monitoring system. It runs checks on a schedule,
shows the current state of every host and service, and alerts you when something breaks
— and again when it is fixed.

<Callout title="Versions used in this guide">
  Nagios Core **4.5.14** · Nagios Plugins **2.5.x** · Apache 2.x or Nginx ·
  PHP 7.0 or newer · Ubuntu 20.04/22.04/24.04 LTS, Debian 10/11/12, RHEL 7/8/9
</Callout>

<Callout title="Nagios Core or Nagios XI?">
  Nagios Core is free and text-configured. **Nagios XI** is the commercial edition built
  on the same engine, with a web-based setup wizard, dashboards, reporting and role-based
  access control. If you want the GUI, use XI; if you want full control and no licence
  cost, stay on Core.
</Callout>

## System Requirements

- 2 CPU cores (4+ recommended for larger deployments)
- 2 GB RAM minimum (4 GB+ recommended)
- 20 GB of free disk space
- Apache 2.x or Nginx as the web server
- PHP 7.0 or newer
- GCC and the standard build tools
- Reliable network connectivity to everything you monitor

## Installation Instructions

Nagios Core is distributed as source, so it is compiled and installed on the host.

    ### Ubuntu / Debian

    ```bash
    # Install the dependencies
    sudo apt update
    sudo apt install -y autoconf automake gcc libc6-dev make libgd-dev libssl-dev \
      libtool pkg-config libxml2-dev libxslt1-dev libcurl4-openssl-dev \
      libltdl-dev libperl-dev libmysqlclient-dev \
      apache2 apache2-utils libapache2-mod-php php php-cli php-gd php-mysql \
      mysql-server unzip wget

    # Create the nagios user and group
    sudo groupadd -r nagios
    sudo useradd -r -g nagios -s /sbin/nologin -d /usr/local/nagios nagios
    sudo usermod -aG nagios www-data

    # Download Nagios Core 4.5.14
    cd /tmp
    curl -LO https://github.com/NagiosEnterprises/nagioscore/archive/nagios-4.5.14.tar.gz
    tar xzf nagios-4.5.14.tar.gz
    cd nagioscore-nagios-4.5.14

    # Compile and install
    sudo ./configure --with-httpd-conf=/etc/apache2/sites-enabled --with-httpd-user=www-data
    sudo make all
    sudo make install
    sudo make install-daemoninit
    sudo make install-commandmode
    sudo make install-config
    sudo make install-webconf

    # Install the Nagios Plugins
    cd /tmp
    curl -LO https://github.com/nagios-plugins/nagios-plugins/archive/release-2.5.tar.gz
    tar xzf release-2.5.tar.gz
    cd nagios-plugins-release-2.5
    sudo ./tools/setup
    sudo ./configure
    sudo make
    sudo make install

    # Create the web interface user
    sudo htpasswd -c /usr/local/nagios/etc/htpasswd.users nagiosadmin

    # Enable the Apache modules
    sudo a2enmod rewrite
    sudo a2enmod cgi
    sudo a2enmod php

    # Start the services
    sudo systemctl restart apache2
    sudo systemctl enable --now nagios
    ```
  </TabsContent>

## Configuration

### Hosts and Services

Create `/usr/local/nagios/etc/objects/hosts.cfg`:

```cfg
define host {
    use                     linux-server
    host_name               web1
    alias                   Web Server 1
    address                 192.168.1.10
    check_command           check-host-alive
    max_check_attempts      5
    check_period            24x7
    notification_period     24x7
    notification_options    d,u,r
    contact                 nagiosadmin
}
```

Create `/usr/local/nagios/etc/objects/services.cfg`:

```cfg
define service {
    host_name               web1
    service_description     HTTP
    check_command           check_http
    max_check_attempts      3
    check_interval          5
    retry_interval          1
    check_period            24x7
    notification_period     24x7
    notification_options    w,u,c,r
    contact                 nagiosadmin
}

define service {
    host_name               web1
    service_description     SSH
    check_command           check_ssh
    check_interval          5
    retry_interval          1
    max_check_attempts      3
}
```

### Host Templates

`/usr/local/nagios/etc/objects/templates.cfg`:

```cfg
define host {
    name                    linux-server
    use                     generic-host
    check_command           check-host-alive
    check_period            24x7
    notification_period     24x7
    notification_options    d,u,r
    contact                 nagiosadmin
    register                0
}

define host {
    name                    generic-host
    notifications_enabled   1
    event_handler_enabled   1
    flap_detection_enabled  1
    process_perf_data       1
    retain_status_information 1
    retain_nonstatus_information 1
    notification_period     24x7
    register                0
}
```

### Verifying the Configuration

```bash
# Validate the configuration
sudo /usr/local/nagios/bin/nagios -v /usr/local/nagios/etc/nagios.cfg

# Reload after a change (no downtime)
sudo systemctl reload nagios
```

## Verifying the Installation

```bash
# The service is running
sudo systemctl status nagios

# The plugins work
sudo /usr/local/nagios/libexec/check_dns -H localhost -v
sudo /usr/local/nagios/libexec/check_http -H localhost -v

# The daemon is scheduling checks
ps aux | grep nagios
```

Open `http://<server>/nagios` and sign in with `nagiosadmin` and the password you set.

## Notifications

### Email

```cfg
# /usr/local/nagios/etc/objects/contacts.cfg
define contact {
    use                     generic-contact
    alias                   Nagios Administrator
    email                   admin@example.com
}
```

### Slack or Teams

```cfg
define contact {
    use                     generic-contact
    alias                   Slack Notifier
    email                   slack-notifier@example.com
}
```

```bash
# Install a notification command
sudo wget -O /usr/local/nagios/libexec/slack_notifier.py \
  https://raw.githubusercontent.com/slagSHOT/slack_notifier/master/slack_notifier.py
sudo chmod +x /usr/local/nagios/libexec/slack_notifier.py
```

```cfg
# /usr/local/nagios/etc/commands.cfg
define command {
    command_name    check_slack
    command_line    /usr/local/nagios/libexec/slack_notifier.py -c /etc/nagios/slack_channel -t "$NOTIFICATIONTYPE$ - $SERVICESTATE$ - $SERVICEDESC$" -m "$SERVICEOUTPUT$"
}
```

## Troubleshooting

<Accordion type="single">
  <AccordionItem value="issue-1">
    <AccordionTrigger>
      The web interface shows a 500 error or is blank
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # The Apache error log
      sudo tail -n 50 /var/log/apache2/error.log

      # PHP modules
      sudo a2enmod php
      sudo systemctl restart apache2
      ```
      The most common cause is the `www-data` user not being in the `nagios` group —
      run `sudo usermod -aG nagios www-data` and restart Apache.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-2">
    <AccordionTrigger>
      "Return code of 127" or the check output is empty
    </AccordionTrigger>
    <AccordionContent>
      The plugin cannot be found or a dependency is missing:
      ```bash
      # Run the check by hand
      sudo -u nagios /usr/local/nagios/libexec/check_http -H localhost -v

      # Check the permissions
      sudo ls -l /usr/local/nagios/libexec/check_http
      ```
      Exit code 127 means the binary or one of its libraries is missing — install the
      matching `lib*` package.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-3">
    <AccordionTrigger>
      No notifications are sent
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # Is the contact assigned to the host and service?
      sudo grep -r "nagiosadmin" /usr/local/nagios/etc/objects/

      # Are notifications enabled at all?
      sudo grep notifications_enabled /usr/local/nagios/etc/nagios.cfg

      # Test the command by hand
      sudo -u nagios /usr/local/nagios/libexec/slack_notifier.py -c test
      ```
      Remember to reload Nagios after every configuration change.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-4">
    <AccordionTrigger>
      Checks are running but the status never changes
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # Is the check interval set?
      sudo grep check_interval /usr/local/nagios/etc/objects/services.cfg

      # Is the passive check cache being updated?
      sudo ls -l /usr/local/nagios/var/spool/checkresults
      ```
      `check_interval` of 0 means the check is passive — it only runs when a passive
      result arrives.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-5">
    <AccordionTrigger>
      The configuration will not load
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # The validation output names the file and the line
      sudo /usr/local/nagios/bin/nagios -v /usr/local/nagios/etc/nagios.cfg
      ```
      A missing semicolon or a misspelled directive stops the whole file from loading.
      The same command validates the configuration before every reload, so run it in CI
      against your configuration repository.
    </AccordionContent>
  </AccordionItem>
</Accordion>

## Best Practices

1. **Keep the configuration in Git** and deploy it — Nagios configuration files are
   code.
2. **Validate before every reload** with `nagios -v`.
3. **Use host and service templates** so a new host takes three lines, not thirty.
4. **Set `notification_options` deliberately** — `d,u,r` sends down, unreachable and
   recovery notifications.
5. **Use `max_check_attempts` above 1** for services so a single blip does not page
   anyone.
6. **Monitor Nagios itself** — a check on the Nagios server from a second host.
7. **Prefer `check_by_ssh` or NRPE** for checks that must run on the target host, so you
   do not open a network port to every machine.
8. **Prune old performance data** with `nagios --prune` so the database does not grow
   without bound.
9. **Do not monitor everything** — a noisy monitor gets ignored.
