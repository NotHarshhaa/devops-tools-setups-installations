Git is the distributed version control system that every DevOps workflow is built on. This
guide installs the current release and configures the parts that matter day to day.

<Callout title="Versions used in this guide">
  Git **2.56.0** (released September 2026) · `git switch` / `git restore` ·
  **Git Credential Manager** for storing credentials · commit signing with an SSH or
  GPG key
</Callout>

<Callout title="Your distribution's package is often older">
  `apt install git` gives you whatever the distribution shipped — sometimes several
  releases behind. That is fine for most work, but if you need the newest Git (for a
  new flag or a security fix), build it from source or use a version manager.
</Callout>

## System Requirements

- A 64-bit operating system: Linux, macOS or Windows
- For building from source: GCC 4.9+ or Clang, Make, `zlib1g-dev`, `libssl-dev`,
  `libcurl4-openssl-dev`, `libexpat1-dev`, `gettext`, `libpcre2-dev` and `pkg-config`
- About 200 MB of disk space for a full build

    ### macOS

    macOS ships with an old Git (the Xcode command line tools version). Install a current
    one with Homebrew:

    ```bash
    brew install git

    # Make the Homebrew version the default
    echo 'export PATH="/opt/homebrew/bin:$PATH"' >> ~/.zshrc
    source ~/.zshrc

    git --version
    ```

    Check which Git you are actually running:

    ```bash
    which -a git
    ```
  </TabsContent>

  <TabsContent value="windows">
    ### Windows

    ```powershell
    # Windows Package Manager (Git for Windows)
    winget install --id Git.Git -e --source winget

    # Chocolatey
    choco install git -y
    ```

    Or download the installer from [git-scm.com/download/win](https://git-scm.com/download/win)
    and make sure to select **"Git from the command line and also from 3rd-party software"**
    so it ends up on your `PATH`.
  </TabsContent>

  <TabsContent value="source">
    ### From Source (latest release)

    ```bash
    # Install the build dependencies
    sudo apt update
    sudo apt install -y build-essential libssl-dev libcurl4-openssl-dev \
      zlib1g-dev libexpat1-dev gettext libpcre2-dev pkg-config

    # Download and build the latest release
    cd /tmp
    curl -LO https://www.kernel.org/pub/software/scm/git/git-2.56.0.tar.gz
    tar xzf git-2.56.0.tar.gz
    cd git-2.56.0

    make prefix=/usr/local
    sudo make prefix=/usr/local install

    # Verify
    git --version
    ```
  </TabsContent>

  <TabsContent value="versioned">
    ### Version Manager

    Use a version manager when different projects need different Git versions:

    ```bash
    # mise (works on Linux, macOS and Windows)
    curl https://mise.run | sh
    mise use -g git@2.56.0
    git --version

    # asdf
    asdf plugin add git
    asdf install git latest
    asdf global git latest
    ```

## Post-Installation Configuration

### Identity

```bash
# Your name and email — these end up in every commit you make
git config --global user.name "Your Name"
git config --global user.email "you@example.com"

# The default branch for new repositories
git config --global init.defaultBranch main

# The editor for commit messages
git config --global core.editor "code --wait"   # or vim, nano, ...

# Check what is set
git config --global --list
```

### A Sensible Default Setup

```bash
# Pull with rebase instead of merge commits
git config --global pull.rebase true

# Reuse conflict resolutions when rebasing
git config --global rerere.enabled true

# Show the original object when a file is renamed
git config --global diff.renames copies

# Prune deleted branches when fetching
git config --global fetch.prune true

# Use the native file system monitor on macOS and Windows
git config --global core.fsmonitor true
```

### SSH Keys

```bash
# 1. Generate an ed25519 key
ssh-keygen -t ed25519 -C "you@example.com"

# 2. Start the agent and add the key (macOS)
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

# On Linux with systemd, enable the agent once
sudo systemctl enable --now ssh-agent
```

```bash
# 3. Copy the public key to the host
ssh-copy-id -i ~/.ssh/id_ed25519.pub you@server

# 4. Test it
ssh -T git@github.com
```

Use a different key per service with `~/.ssh/config`:

```text
Host github.com
  IdentityFile ~/.ssh/id_ed25519_github
  AddKeysToAgent yes

Host gitlab.com
  IdentityFile ~/.ssh/id_ed25519_gitlab
```

### Credential Storage

Do not store passwords in plain text. Use **Git Credential Manager**, which stores them in
the OS keychain:

```bash
# Linux, macOS and Windows with Git Credential Manager installed
git config --global credential.helper manager

# macOS only — the system keychain
git config --global credential.helper osxkeychain

# Windows only — the Windows Credential Manager
git config --global credential.helper manager
```

```bash
# Check which helper is active
git config --global credential.helper
git credential fill   # type protocol=https, host=github.com and press Ctrl-D
```

### Signing Your Commits

Since Git 2.34 you can sign with an **SSH key** — no GPG needed:

```bash
# Use the SSH key format
git config --global gpg.format ssh

# The key to sign with
git config --global user.signingkey ~/.ssh/id_ed25519.pub

# Sign every commit automatically
git config --global commit.gpgsign true

# And every tag
git config --global tag.gpgsign true
```

```bash
# Verify a signature
git log --show-signature -1
```

## Everyday Commands

```bash
# Start a repository and commit
git init
git add .
git commit -m "Initial commit"

# Branching — the modern commands
git switch -c feature/login        # create and switch
git switch main                     # switch back
git switch -                        # switch to the previous branch
git branch -d feature/login        # delete a merged branch

# Undo changes
git restore file.txt                # discard unstaged changes
git restore --staged file.txt       # unstage
git restore --source=HEAD file.txt  # discard changes to a file
git commit --amend                  # fix the last commit

# Unstage
git reset HEAD file.txt

# See what changed
git status
git diff
git diff --staged
git log --oneline --graph --decorate

# Pull with rebase
git pull --rebase

# Sync a branch with the main branch
git rebase main
# or merge the other way
git merge main

# Undo a merge or rebase
git reset --hard ORIG_HEAD

# Stash work in progress
git stash push -m "wip"
git stash list
git stash pop

# Worktrees — a second checkout of the same repository
git worktree add ../myapp-feature feature/login
```

## Troubleshooting

<Accordion type="single">
  <AccordionItem value="issue-1">
    <AccordionTrigger>
      "command not found: git" after installation
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # Where is it?
      which -a git

      # Add it to your PATH (macOS with Homebrew)
      echo 'export PATH="/opt/homebrew/bin:$PATH"' >> ~/.zshrc
      source ~/.zshrc
      ```
      On Windows, reopen the terminal after installing so it picks up the new `PATH`.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-2">
    <AccordionTrigger>
      The wrong version of Git is being used
    </AccordionTrigger>
    <AccordionContent>
      macOS ships its own Git, and the Xcode command line tools take precedence:
      ```bash
      which -a git
      /usr/bin/git --version   # the system version
      ```
      Put the Homebrew path first in your `PATH`, or use a version manager.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-3">
    <AccordionTrigger>
      "Permission denied (publickey)" when pushing
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # Is the key loaded?
      ssh-add -l

      # Does the server accept this key?
      ssh -T git@github.com

      # Which key is being used?
      ssh -vT git@github.com 2>&1 | grep "Offering"
      ```
      If the agent is not running, `eval "$(ssh-agent -s)"` and `ssh-add` the key. If the
      server has an old key, remove it from your account and add the new public key.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-4">
    <AccordionTrigger>
      SSL certificate errors
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # Update the system certificates
      sudo apt update && sudo apt install -y ca-certificates
      sudo update-ca-certificates

      # Check what Git is using
      git config --show-origin --get http.sslCAInfo
      ```
      Behind a TLS-inspecting proxy, point Git at the corporate CA:
      ```bash
      git config --global http.sslCAInfo /usr/local/share/ca-certificates/company.crt
      ```
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-5">
    <AccordionTrigger>
      "detected dubious ownership" in a repository
    </AccordionTrigger>
    <AccordionContent>
      Git refuses to work in a directory owned by another user — this is a safety check
      against symlink attacks:
      ```bash
      sudo chown -R $(id -u):$(id -g) /path/to/repo

      # Or tell Git the directory is safe
      git config --global --add safe.directory /path/to/repo
      ```
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-6">
    <AccordionTrigger>
      The repository is slow or huge
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # Let Git notice file changes instead of scanning everything
      git config --global core.fsmonitor true

      # Clean up and repack
      git maintenance run --auto
      git gc --aggressive --prune=now

      # See the biggest objects in the history
      git count-objects -vH
      ```
      For very large repositories, a partial clone (`git clone --filter=blob:none`) keeps
      the history local but fetches blobs on demand.
    </AccordionContent>
  </AccordionItem>
</Accordion>

## Best Practices

1. **Set your identity once** and use `git config --global` so every repository inherits it.
2. **Use `git switch` and `git restore`** instead of the older `git checkout` — they are
   explicit about what they change.
3. **Never commit secrets.** Use `.gitignore` from day one, and add a secret scanner to
   your pre-commit hooks.
4. **Sign your commits** — with an SSH key it costs nothing and proves the commit is
   yours.
5. **Use a credential helper**, never a password in the remote URL.
6. **Rebase your branch before opening a pull request** so the history stays linear.
7. **Set `pull.rebase true`** so a pull never creates an accidental merge commit.
8. **Enable `rerere`** so a resolved conflict is remembered for the next rebase.
9. **Use `git maintenance run --auto`** (or `git maintenance start`) to keep the
   repository healthy.
10. **Prefer `gh` and `glab`** for pull requests, issues and pipelines — they handle the
    API details and authentication for you.
