GitLab CLI (`glab`) is the official GitLab command-line tool. It handles merge requests,
issues, pipelines, runners and releases — and it detects the GitLab instance from the
remotes in your working directory.

<Callout title="Versions used in this guide">
  GitLab CLI **1.124.0** · requires **GitLab 16.0 or newer** · Homebrew is the officially
  supported package manager · `glab duo cli` for GitLab Duo in the terminal
</Callout>

<Callout title="Homebrew is the officially supported install method">
  The GitLab CLI project officially supports Homebrew on macOS, Linux and WSL. Everything
  else — the `.deb`/`.rpm` packages, the distro packages and the container image — is
  maintained by the community and may lag behind.
</Callout>

## System Requirements

- A 64-bit operating system: Linux, macOS or Windows
- `git` on your `PATH`
- A GitLab.com, GitLab Dedicated or GitLab Self-Managed instance on **GitLab 16.0 or
  later** — some commands need even newer versions

    ```bash
    curl -LO "https://gitlab.com/gitlab-org/cli/-/releases/v1.124.0/downloads/glab_1.124.0_linux_amd64.rpm"
    sudo rpm -Uvh glab_1.124.0_linux_amd64.rpm
    ```

    <Callout title="Snap needs extra connections">
      A snap-installed `glab` cannot see your SSH keys or keychain until you connect them:
      ```bash
      sudo snap install glab
      sudo snap connect glab:ssh-keys
      sudo snap connect glab:password-manager-service
      ```
      Without the keychain connection, `glab auth login` falls back to plaintext storage.
    </Callout>

## Authentication

`glab` supports OAuth, personal access tokens and CI job tokens.

```bash
# Interactive login
glab auth login

# Log in to a self-managed instance
glab auth login --hostname gitlab.example.com

# Non-interactive login with a token
echo "$GITLAB_TOKEN" | glab auth login --stdin

# Check the current state
glab auth status

# Log out
glab auth logout
```

```bash
# In CI, the token is simply an environment variable
export GITLAB_TOKEN=glpat-xxxxxxxxxxxx
export CI_SERVER_URL=https://gitlab.com
```

| Variable | Purpose |
| --- | --- |
| `GITLAB_TOKEN` | Token used for API requests |
| `GITLAB_HOST` | Default instance URL |
| `GLAB_CONFIG_DIR` | Where the configuration is stored |
| `GLAB_DEBUG` | Set to `true` for verbose logging, including the underlying git commands |

## Everyday Commands

### Merge Requests

```bash
# Create a merge request
glab mr create --title "Add login" --description "Closes #42" --source-branch feature/login

# List, view and check out
glab mr list --assignee=@me
glab mr list --reviewer=@me
glab mr view 235
glab mr checkout 235

# Review and merge
glab mr approve 235
glab mr merge 235 --squash --remove-source-branch
```

### Issues

```bash
# Create and list
glab issue create -m release-2.0.0 -t "My title here" --label important
glab issue list --assignee=@me

# Update and close
glab issue update 42 --label "needs review"
glab issue close 42
```

### Pipelines and Jobs

```bash
# List and inspect
glab pipeline list
glab pipeline view 12345
glab pipeline status

# Follow a job log
glab ci list
glab ci view 98765
glab ci trace 98765

# Retry a failed job
glab ci retry 98765
```

### Repositories and Releases

```bash
# Repository
glab repo clone owner/repo
glab repo fork owner/repo
glab repo view

# Releases and changelogs
glab release create v1.2.0 --notes "Bug fixes"
glab changelog generate
```

### Runners, Agents and Variables

```bash
# Runners
glab runner list
glab runner create --name my-runner --executor docker

# GitLab Agents for Kubernetes
glab cluster agent list

# Project and group variables
glab variable set LOG_LEVEL --scope project --value debug
glab variable list
```

### GitLab Duo in the Terminal

```bash
# Ask GitLab Duo about the codebase
glab duo cli

# Or a one-off question
glab duo chat "explain this module"
```

## Troubleshooting

<Accordion type="single">
  <AccordionItem value="issue-1">
    <AccordionTrigger>
      Authentication errors or 401 responses
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # What does glab think is authenticated?
      glab auth status

      # Log in again
      glab auth logout
      glab auth login

      # Turn on debug logging
      GLAB_DEBUG=true glab mr list
      ```
      A token without the `api` scope fails on every API call. Personal access tokens
      need at least `api` (or `read_api` for read-only work).
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-2">
    <AccordionTrigger>
      glab talks to the wrong GitLab instance
    </AccordionTrigger>
    <AccordionContent>
      `glab` detects the host from your git remotes. Check what it resolves to:
      ```bash
      git remote -v
      glab auth status
      ```
      Set the host explicitly:
      ```bash
      glab auth status --hostname gitlab.example.com
      export GITLAB_HOST=https://gitlab.example.com
      ```
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-3">
    <AccordionTrigger>
      The repository cannot be found
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # Are you inside a repository with a GitLab remote?
      git remote -v

      # Point glab at it explicitly
      glab repo view --repo owner/repo
      ```
      For GitLab subgroups, use the full path: `glab mr list --repo group/subgroup/project`.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-4">
    <AccordionTrigger>
      Commands fail with "not found" on an older instance
    </AccordionTrigger>
    <AccordionContent>
      `glab` supports GitLab 16.0 and later, and some commands need a newer version than
      that. Check what your instance offers:
      ```bash
      glab api version
      ```
      Upgrade the instance, or use the REST API directly with `glab api` for the calls
      your version does not support.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-5">
    <AccordionTrigger>
      The pipeline log is empty
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # The job may still be running
      glab ci status

      # Fetch the raw log
      glab ci trace 98765 --raw
      ```
      Traces are only available for jobs that have finished and are retained for a limited
      time — download the log before it expires.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-6">
    <AccordionTrigger>
      The command is not found
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      which glab
      glab --version
      ```
      The Homebrew formula installs into `/opt/homebrew/bin` on Apple silicon — make sure
      that is on your `PATH`. A `.deb` install puts the binary in `/usr/bin/glab`.
    </AccordionContent>
  </AccordionItem>
</Accordion>

## Best Practices

1. **Install with Homebrew** — it is the officially supported method and always has the
   current release.
2. **Use a scoped token**: `read_api` for read-only automation, `api` only when you
   really need to write.
3. **Set `GITLAB_TOKEN` in CI** instead of running the interactive login.
4. **Turn on `GLAB_DEBUG=true`** when something behaves strangely — it shows the git
   commands and the API calls.
5. **Use `glab api`** for anything the CLI does not wrap.
6. **Use `glab runner` and `glab cluster agent`** to manage runners and agents instead
   of the web UI.
7. **Pin the CLI version** in CI images so a new release cannot change your pipeline.
8. **Never commit a token** — use CI variables and masked, protected project variables.
