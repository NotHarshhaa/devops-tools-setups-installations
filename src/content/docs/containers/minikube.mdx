Minikube runs a single-node Kubernetes cluster locally, inside a container or a virtual
machine. This guide installs **Minikube v1.39** and walks through the commands you use
every day.

<Callout title="Minikube is for learning and development">
  Minikube is not a production platform. For a real cluster, use the
  [kubeadm guide](/docs/containers/kubernetes) or a managed Kubernetes service.
</Callout>

## Prerequisites

- 2 CPUs or more
- 2 GB of free memory (4 GB or more recommended)
- 20 GB of free disk space
- Internet access to pull images
- A container or virtual machine driver: Docker, Podman, QEMU, KVM, Hyper-V, VirtualBox,
  VMware Fusion/Workstation or Parallels

### macOS

```bash
# Homebrew (recommended)
brew install minikube

# Or the binary
curl -LO https://github.com/kubernetes/minikube/releases/latest/download/minikube-darwin-arm64
sudo install minikube-darwin-arm64 /usr/local/bin/minikube
```

If `which minikube` fails after a Homebrew install, relink it:

```bash
brew unlink minikube
brew link minikube
```

### Windows

```powershell
# Windows Package Manager
winget install Kubernetes.minikube

# Chocolatey
choco install minikube

# Or the .exe installer
# https://storage.googleapis.com/minikube/releases/latest/minikube-installer.exe
```

### Install kubectl

Minikube can download a matching `kubectl` for you, but having a standalone client is
handy:

```bash
KUBECTL_VERSION="$(curl -sL https://dl.k8s.io/release/stable.txt)"
curl -LO "https://dl.k8s.io/release/${KUBECTL_VERSION}/bin/linux/amd64/kubectl"
sudo install -o root -g root -m 0755 kubectl /usr/local/bin/kubectl
```

## Starting the Cluster

```bash
# Start with the default driver (Docker if it is available)
minikube start

# Explicitly choose a driver
minikube start --driver=docker
minikube start --driver=podman
minikube start --driver=kvm2

# Give the cluster more resources
minikube start --cpus=4 --memory=8192mb

# Start a multi-node cluster
minikube start --nodes=3

# Pin a Kubernetes version (one of the three latest minor releases)
minikube start --kubernetes-version=v1.36.0

# Use containerd instead of the Docker runtime inside the node
minikube start --container-runtime=containerd
```

On Windows, Hyper-V must be enabled before starting Minikube:

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V -All
```

### Verify the Cluster

```bash
# Cluster status
minikube status

# Nodes
kubectl get nodes -o wide

# System pods
kubectl get pods -A

# Or use the bundled kubectl
minikube kubectl -- get pods -A
```

Add an alias so `kubectl` always targets the cluster:

```bash
echo 'alias kubectl="minikube kubectl --"' >> $HOME/.bashrc
source $HOME/.bashrc
```

## Deploying Your First Application

```bash
# Create a deployment and expose it
kubectl create deployment hello-minikube --image=kicbase/echo-server:1.0
kubectl expose deployment hello-minikube --type=NodePort --port=8080

# Open it in a browser
minikube service hello-minikube

# Or forward the port instead
kubectl port-forward service/hello-minikube 7080:8080
```

For a `LoadBalancer` service, run the tunnel in a separate terminal:

```bash
minikube tunnel
```

Then read the external IP from `kubectl get services`.

## Managing Add-ons

```bash
# List the available add-ons
minikube addons list

# Enable the ingress controller
minikube addons enable ingress

# Enable the dashboard
minikube addons enable dashboard

# Open the dashboard
minikube dashboard

# Disable an add-on
minikube addons disable ingress
```

<Callout title="Ingress needs a tunnel">
  With the Docker driver, the ingress address is only reachable while `minikube tunnel`
  is running. Use `127.0.0.1` instead of the advertised address when testing locally.
</Callout>

## Working with Images

Building locally is slow because the image has to travel to the node. Load it directly
instead:

```bash
# Build with the host daemon
docker build -t my-app:1.0 .

# Load the image into the Minikube node
minikube image load my-app:1.0

# Or point your shell at the in-cluster daemon
eval $(minikube docker-env)
docker build -t my-app:1.0 .

# Return to the host daemon
eval $(minikube docker-env -u)
```

## Managing Clusters

```bash
# Create a second cluster with an older Kubernetes version
minikube start -p aged --kubernetes-version=v1.35.0

# List the profiles
minikube profile list

# Switch between them
minikube profile aged

# Pause and resume
minikube pause
minikube unpause

# Stop and delete
minikube stop
minikube delete
minikube delete --all

# Change the defaults for the next start
minikube config set memory 9001
minikube config set cpus 4
```

## Troubleshooting

<Accordion type="single">
  <AccordionItem value="issue-1">
    <AccordionTrigger>
      Unable to start the cluster / exit code 127
    </AccordionTrigger>
    <AccordionContent>
      Minikube could not find or start your container runtime or hypervisor:
      ```bash
      # Check the driver status
      minikube start --driver=docker
      systemctl status docker

      # Get verbose logs
      minikube start --alsologtostderr -v=4

      # Start from a clean state
      minikube delete
      ```
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-2">
    <AccordionTrigger>
      Connection refused when talking to the cluster
    </AccordionTrigger>
    <AccordionContent>
      The cluster is probably stopped or was moved to another profile:
      ```bash
      minikube status
      minikube profile list
      minikube start
      ```
      Confirm the kubeconfig context points at the right cluster with
      `kubectl config current-context`.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-3">
    <AccordionTrigger>
      The Docker driver fails with permission errors
    </AccordionTrigger>
    <AccordionContent>
      Minikube needs access to the Docker socket:
      ```bash
      sudo usermod -aG docker $USER
      newgrp docker

      # If you use rootless Docker, make sure the daemon is running
      # and that $DOCKER_HOST points at the rootless socket
      systemctl --user status docker
      echo $DOCKER_HOST
      ```
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-4">
    <AccordionTrigger>
      ImagePullBackOff after deploying an application
    </AccordionTrigger>
    <AccordionContent>
      The node cannot reach the registry, or the image only exists on your machine:
      ```bash
      # Load a locally built image into the node
      minikube image load my-app:1.0

      # Check the pull error
      kubectl describe pod <pod-name>
      ```
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-5">
    <AccordionTrigger>
      The dashboard or ingress address is not reachable
    </AccordionTrigger>
    <AccordionContent>
      Run the tunnel and use the loopback address:
      ```bash
      minikube tunnel
      kubectl get ingress
      # Use http://127.0.0.1:<port> in the browser
      ```
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-6">
    <AccordionTrigger>
      The cluster is slow or out of resources
    </AccordionTrigger>
    <AccordionContent>
      Check what the node is actually using and raise the limits:
      ```bash
      kubectl top nodes
      minikube stop
      minikube start --cpus=4 --memory=8192mb
      ```
      On macOS and Windows, giving the virtual machine more memory in the hypervisor
      settings helps as well.
    </AccordionContent>
  </AccordionItem>
</Accordion>

## Best Practices

1. **Use a named profile per project** so teams do not overwrite each other's cluster:
   ```bash
   minikube start -p payments
   ```

2. **Pin the Kubernetes version** in CI so a new Minikube release cannot change your
   test matrix under you.

3. **Load images instead of pulling them** — it is dramatically faster:
   ```bash
   minikube image build -t my-app:1.0 .
   ```

4. **Keep the cluster small** — one node with 2 CPUs is enough for most development work.

5. **Reset when things get weird** — a fresh cluster is faster to fix than a broken one:
   ```bash
   minikube delete
   minikube start
   ```
