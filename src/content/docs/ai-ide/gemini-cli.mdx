Gemini CLI is Google's open-source terminal agent (Apache 2.0). It ships weekly releases
with a `preview`, `stable` and `nightly` channel.

<Callout title="Gemini CLI is being replaced by Antigravity CLI">
  On **18 June 2026** Gemini CLI and the Gemini Code Assist IDE extensions stopped serving
  requests for Google AI Pro and Ultra users and for people using it for free. Google
  has moved its effort into **Antigravity CLI** and Antigravity 2.0, a multi-agent
  platform. Gemini CLI still works with a paid Gemini API key or Gemini Enterprise Agent
  Platform API key.
</Callout>

## System Requirements

- Node.js 20 or newer (22+ recommended)
- A Google account, a Gemini API key, or a Google Cloud project with Vertex AI enabled
- macOS, Linux or Windows (WSL2 recommended on Windows)

## Installation Instructions

```bash
# Run it without installing anything
npx @google/gemini-cli

# Install globally with npm
npm install -g @google/gemini-cli

# Install with Homebrew (macOS and Linux)
brew install gemini-cli
```

```bash
# macOS with MacPorts
sudo port install gemini-cli
```

```bash
# In a Conda environment (restricted networks)
conda create -y -n gemini_env -c conda-forge nodejs
conda activate gemini_env
npm install -g @google/gemini-cli
```

### Release Channels

```bash
# Stable — the full promotion of last week's preview release
npm install -g @google/gemini-cli@latest

# Preview — published every Tuesday at 23:59 UTC
npm install -g @google/gemini-cli@preview

# Nightly — every change from main, published daily
npm install -g @google/gemini-cli@nightly
```

### Migrating to Antigravity CLI

```bash
# Download Antigravity CLI
# https://antigravity.google/download

# The migration guide
# https://antigravity.google/docs/gcli-migration
```

Antigravity CLI is written in Go, so it is faster, and it keeps the parts people relied
on most: Agent Skills, hooks, subagents and extensions (now Antigravity plugins). The
migration guide covers moving your settings, MCP servers and provider configuration.

## Authentication

### Sign in with Google

```bash
# Interactive OAuth login
gemini

# Or set the project for a paid Code Assist licence
export GOOGLE_CLOUD_PROJECT="YOUR_PROJECT_ID"
gemini
```

### Gemini API Key

```bash
# Get a key at https://aistudio.google.com/apikey
export GEMINI_API_KEY="YOUR_API_KEY"
gemini
```

### Vertex AI

```bash
# For enterprise use and higher rate limits
export GOOGLE_API_KEY="YOUR_API_KEY"
export GOOGLE_GENAI_USE_VERTEXAI=true
gemini
```

## Using the CLI

```bash
# Start an interactive session in the current directory
gemini

# Include more directories in the context
gemini --include-directories ../lib,../docs

# Pick a model
gemini -m gemini-2.5-flash
```

### Headless and Scripting Mode

```bash
# A simple text response
gemini -p "Explain the architecture of this codebase"

# Structured output
gemini -p "Explain the architecture of this codebase" --output-format json

# Stream events for long-running operations
gemini -p "Run the tests and deploy" --output-format stream-json
```

## Project Context

Create a `GEMINI.md` in the project root to give the agent persistent context. Commit it
so the whole team shares the same instructions:

```markdown
# GEMINI.md

- Run `npm run lint && npm test` before reporting a change as done.
- Never edit files under `migrations/` without asking first.
- Use the repository pattern in `src/repositories/` for all database access.
```

## MCP Servers and Extensions

```bash
# Configure an MCP server in ~/.gemini/settings.json
```

```json
{
  "mcpServers": {
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "${GITHUB_TOKEN}" }
    }
  }
}
```

```text

> @slack Send a summary of today's commits to #dev
```

## Troubleshooting

<Accordion type="single">
  <AccordionItem value="issue-1">
    <AccordionTrigger>
      The command is not found
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # Did the global install land on your PATH?
      npm prefix -g
      which gemini

      # Node 20 or newer is required
      node --version
      ```
      Add the npm global bin directory to your `PATH` if it is missing.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-2">
    <AccordionTrigger>
      Authentication fails or the request is rejected
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # Which account and project are active?
      gcloud auth list
      echo $GEMINI_API_KEY
      echo $GOOGLE_CLOUD_PROJECT
      ```
      If you recently moved to Antigravity CLI, the free tier no longer serves Gemini CLI
      requests — migrate, or use a paid API key.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-3">
    <AccordionTrigger>
      The agent will not run commands
    </AccordionTrigger>
    <AccordionContent>
      The CLI asks for approval the first time it runs a command in a folder. To control
      this per project, set the policy in `~/.gemini/settings.json`:
      ```json
      {
        "tools": { "allowed": ["run_shell_command"], "denied": ["run_shell_command(rm:*)"] }
      }
      ```
      Trusted folders let you decide which directories the agent may operate in.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-4">
    <AccordionTrigger>
      Usage limits are hit immediately
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # Use a paid API key instead of the free tier
      export GEMINI_API_KEY="YOUR_API_KEY"

      # Or switch to Vertex AI for higher limits
      export GOOGLE_GENAI_USE_VERTEXAI=true
      export GOOGLE_API_KEY="YOUR_API_KEY"
      ```
    </AccordionContent>
  </AccordionItem>
</Accordion>

## Best Practices

1. **Commit a `GEMINI.md`** so the agent knows your conventions on every machine.
2. **Use headless mode in CI** with `--output-format json` and parse the result.
3. **Pin the channel** — use `@latest` for stability, `@nightly` only to test new features.
4. **Keep API keys in a secret store**, never in a committed `.env`.
5. **Use trusted folders** so the agent does not operate outside your project.
6. **Add MCP servers for the systems you use** — pull requests, chat and issue trackers all
   work as tools.
7. **Migrate to Antigravity CLI** if you are on the free tier or want the multi-agent
   workflow.
