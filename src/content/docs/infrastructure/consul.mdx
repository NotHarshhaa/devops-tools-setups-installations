description: Install Consul 2.0, run a client-server cluster with ACLs and TLS, register services with health checks, and set up service discovery and the service mesh.
---

Consul is a service networking platform. It provides service discovery, distributed
configuration, health checking and — with Connect — mutual TLS between every service in
your mesh.

<Callout title="Versions used in this guide">
  Consul **2.0.4** (2.1 is in release candidate) · client/server cluster with
  Integrated Storage · ACLs with a `default_policy` of `deny` · `service-intentions`
  config entries · **transparent proxy now uses nftables instead of iptables**
</Callout>

<Callout title="Consul 2.0 changed transparent proxy to nftables">
  The transparent proxy no longer manages `iptables`/`ip6tables` rules — it uses
  `nftables` and needs the `nft` binary plus a kernel with stateful NAT support in the
  `inet` family (Linux 5.2+, or a distribution that backports it). There is **no
  fallback** to iptables, and the old iptables rules are **not** cleaned up
  automatically. When upgrading an existing host, remove the old Consul-managed
  iptables rules first, or traffic will be redirected twice.
</Callout>

## System Requirements

- A 64-bit operating system (Linux, macOS, Windows, FreeBSD)
- 2 GB RAM for a small cluster, 4 GB or more per server in production
- Ports 8300 (server RPC), 8301 (serf LAN/WAN), 8302 (Serf), 8500 (HTTP API and UI),
  8600 (DNS) and 443/8200 (Consul Connect)
- A writable data directory for each agent

## Configuration

### Server

Create `/etc/consul.d/server.hcl`:

```hcl
datacenter = "dc1"
data_dir   = "/opt/consul"
node_name  = "consul-server-1"

server = true
bootstrap_expect = 3

bind_addr        = "{{GetPrivateIP}}"
client_addr      = "0.0.0.0"
advertise_addr   = "{{GetInterfaceIP \"ens5\"}}"

retry_join = [
  "10.0.0.11",
  "10.0.0.12",
  "10.0.0.13",
]

ui_config {
  enabled = true
}

# Deny by default — every service needs an explicit intention
acl {
  enabled                  = true
  default_policy           = "deny"
  enable_token_persistence = true
}
```

### Client

Create `/etc/consul.d/client.hcl`:

```hcl
datacenter = "dc1"
data_dir   = "/opt/consul"
node_name  = "app-server-1"

server = false

bind_addr = "{{GetPrivateIP}}"

retry_join = [
  "10.0.0.11",
  "10.0.0.12",
  "10.0.0.13",
]
```

```bash
# Prepare the data directory
sudo mkdir -p /opt/consul
sudo chown -R consul:consul /opt/consul
sudo chmod 750 /opt/consul

# Start the service
sudo systemctl enable --now consul
sudo systemctl status consul
```

## Development Mode

```bash
# Start a single agent with everything enabled
consul agent -dev

# The UI is on http://localhost:8500
consul members
consul services
```

## Security Configuration

### TLS

```bash
# Generate a CA and a server certificate
consul tls ca create
consul tls cert create -server -dc=dc1
```

```hcl
verify_incoming        = true
verify_outgoing        = true
verify_server_hostname = true
ca_file   = "consul-agent-ca.pem"
cert_file = "dc1-server-consul-0.pem"
key_file  = "dc1-server-consul-0-key.pem"
```

### ACLs

```bash
# Bootstrap the ACL system — this prints the initial management token
consul acl bootstrap

# Store the token so the agent can use it
echo "CONSUL_HTTP_TOKEN=..." | sudo tee /etc/consul.d/consul.env

# Create a policy for a service
consul acl policy create -name "web-policy" -rules @web-policy.hcl
```

```hcl
# web-policy.hcl
service_prefix "web" {
  policy = "write"
}

node_prefix "" {
  policy = "read"
}
```

```bash
# Create a token for the service
consul acl token create -description "web service" -policy-name web-policy
```

<Callout title="Consul 2.0 requires mesh:write for escape hatches">
  Attaching Envoy extensions (`builtin/lua`, `builtin/wasm`) or the
  `envoy_*_json` escape-hatch overrides to a service now requires `mesh:write` in
  addition to `service:write`. Grant it only to operators who really need it.
</Callout>

## Service Registration

Create `/etc/consul.d/web-service.hcl`:

```hcl
service {
  name = "web"
  port = 8080

  tags = ["prod", "http"]

  check {
    http = "http://localhost:8080/health"
    interval = "10s"
    timeout  = "2s"
  }
}
```

```bash
# Reload the agent configuration
consul reload

# Check that the service is registered and healthy
consul services
consul health checks service web
```

### Service Intentions

Service intentions define who may talk to whom. They are the heart of the mesh
security model:

```hcl
# /etc/consul.d/intentions.hcl
Kind = "service-intentions"
Name = "web"
Sources = [
  {
    Name = "api"
    Action = "allow"
  },
  {
    Name = "*"
    Action = "deny"
  }
]
```

```bash
# Write the config entry
consul config write /etc/consul.d/intentions.hcl

# List the intentions
consul config list -kind service-intentions
```

## Service Mesh (Consul Connect)

```bash
# Enable Connect on a service
consul config write -kind service-defaults -name web <<EOF
{
  "Protocol": "http",
  "Kind": "service-defaults",
  "Name": "web"
}
EOF

# Start a sidecar proxy for a service instance
consul connect proxy -sidecar-for web

# Check the proxy status
consul connect proxy-status
```

<Callout title="Transparent proxy now needs nftables">
  On Consul 2.x, `consul connect redirect-traffic` uses nftables. Install the `nft`
  package, make sure the kernel supports stateful NAT in the `inet` family, and remove
  any Consul-managed iptables rules left over from Consul 1.x before you start the new
  version.
</Callout>

## Upgrading

```bash
# 1. Back up the data directory
sudo systemctl stop consul
sudo tar -czf /var/backups/consul-$(date +%F).tar.gz -C /opt/consul data
sudo systemctl start consul

# 2. Upgrade the package
sudo apt update && sudo apt install --only-upgrade consul

# 3. Restart one server at a time and check the cluster
sudo systemctl restart consul
consul members
consul leader
```

<Callout title="Upgrade Consul servers one at a time">
  Never upgrade all servers at the same time. Upgrade the followers first, check the
  leader and the Raft health, and only then upgrade the leader.
</Callout>

## Troubleshooting

<Accordion type="single">
  <AccordionItem value="issue-1">
    <AccordionTrigger>
      The cluster does not form
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # Who is in the cluster?
      consul members
      consul monitor

      # Check the ports between the nodes
      nc -vz 10.0.0.11 8301
      ```
      Every node needs the same `datacenter` name, the same `cluster_name` (it defaults
      to the datacenter) and a reachable `retry_join` address. Only one node may have
      `bootstrap_expect` set.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-2">
    <AccordionTrigger>
      "Permission denied" on every command
    </AccordionTrigger>
    <AccordionContent>
      ACLs are enabled and the agent has no valid token:
      ```bash
      export CONSUL_HTTP_TOKEN=<token>
      consul members
      ```
      Check the token with `consul acl token read -self`. With a `default_policy` of
      `deny`, an agent without a token can do almost nothing.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-3">
    <AccordionTrigger>
      The service shows up but the health check is failing
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      consul health checks service web
      consul agent monitor
      ```
      The check runs from the agent, not from your workstation — make sure the endpoint
      is reachable from the agent's network.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-4">
    <AccordionTrigger>
      The UI is not reachable
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # Is the UI enabled?
      consul config read ui_config
      # Is the agent listening?
      ss -tlnp | grep 8500
      ```
      `client_addr` must include the address you connect to, and `ui_config.enabled` has
      to be `true` in the server configuration.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-5">
    <AccordionTrigger>
      Transparent proxy fails to set up
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # nftables is required on Consul 2.x
      which nft && nft --version
      sudo nft list ruleset

      # Check the kernel version
      uname -r
      ```
      You need Linux 5.2 or newer (or a backported kernel) for stateful NAT in the
      `inet` family, and the `nft` binary installed. On Consul 1.x hosts, remove the old
      Consul-managed iptables rules before switching.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-6">
    <AccordionTrigger>
      Service discovery returns no results
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # Query the DNS interface
      dig @127.0.0.1 -p 8600 web.service.consul

      # Or the HTTP interface
      consul catalog services
      ```
      DNS on port 8600 must reach the agent. Check that the client is not using a
      resolver that forwards `.consul` queries elsewhere.
    </AccordionContent>
  </AccordionItem>
</Accordion>

## Best Practices

1. **Run at least three servers** spread across failure domains, plus the clients.
2. **Enable ACLs with `default_policy = "deny"`** and issue scoped tokens per service.
3. **Always use TLS** for gossip and RPC, and rotate the certificates.
4. **Define service intentions explicitly** — they are your mesh authorisation policy.
5. **Use `service-intentions` config entries**, not the deprecated legacy intention API.
6. **Register services with meaningful health checks** so discovery only returns
   healthy instances.
7. **Upgrade one server at a time** and check `consul members` in between.
8. **Back up the data directory** before every upgrade.
9. **Use the Helm chart on Kubernetes** with the official Consul image.
