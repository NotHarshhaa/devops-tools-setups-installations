Vagrant builds and manages reproducible development environments. One `Vagrantfile`
describes the machine, and Vagrant takes care of creating, provisioning, connecting to
and tearing it down.

<Callout title="Versions used in this guide">
  Vagrant **2.4.9** · the official HashiCorp `apt`/`rpm` repositories ·
  Vagrant Box **v2** format · providers for VirtualBox, VMware, Hyper-V, libvirt, Docker
  and Podman
</Callout>

## System Requirements

- A 64-bit operating system with hardware virtualization enabled (Intel VT-x or AMD-V)
- 4 GB RAM or more, 2 GB of it available for the guest
- One of the supported providers:

| Provider | Notes |
| --- | --- |
| VirtualBox | Free, works everywhere, slower than KVM |
| libvirt / KVM | The fastest option on Linux |
| VMware Workstation / Fusion | Good performance, needs a licence for some features |
| Hyper-V | The built-in option on Windows |
| Docker / Podman | Container-based, no virtual machine |

    ```bash
    # Add the HashiCorp signing key
    wget -O - https://apt.releases.hashicorp.com/gpg \
      | sudo gpg --dearmor -o /usr/share/keyrings/hashicorp-archive-keyring.gpg

    # Add the repository
    echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/hashicorp-archive-keyring.gpg] https://apt.releases.hashicorp.com $(grep -oP '(?<=UBUNTU_CODENAME=).*' /etc/os-release || lsb_release -cs) main" \
      | sudo tee /etc/apt/sources.list.d/hashicorp.list

    # Install Vagrant
    sudo apt update
    sudo apt install -y vagrant

    # Install a provider (VirtualBox is the easiest starting point)
    sudo apt install -y virtualbox

    ```

## Verifying the Installation

```bash
# Version
vagrant --version

# List the providers Vagrant can use
vagrant provider --list
```

## Your First Vagrantfile

```ruby
# -*- mode: ruby -*-
# vi: set ft=ruby :

Vagrant.configure("2") do |config|
  # The box the machine is created from
  config.vm.box = "bento/ubuntu-24.04"

  # Provider specific settings
  config.vm.provider "virtualbox" do |vb|
    vb.memory = 4096
    vb.cpus = 2
  end

  # A private network so the host can reach the guest
  config.vm.network "forwarded_port", guest: 80, host: 8080
  config.vm.network "private_network", ip: "192.168.56.10"

  # Synchronise the project folder into the guest
  config.vm.synced_folder ".", "/vagrant", type: "virtualbox"

  # Provision with a shell script
  config.vm.provision "shell", inline: <<-SHELL
    sudo apt-get update
    sudo apt-get install -y nginx
  SHELL
end
```

```bash
# Add the box (downloads it once)
vagrant box add bento/ubuntu-24.04

# Validate the configuration
vagrant validate

# Create and start the machine
vagrant up

# SSH into it
vagrant ssh

# Stop it (keeps the disk)
vagrant halt

# Destroy it (removes everything)
vagrant destroy -f
```

## Boxes

A box is a pre-built base image. The catalogue lives on
[Vagrant Cloud](https://app.vagrantup.com/boxes/search).

```bash
# Search for a box
vagrant search ubuntu

# Add a specific version
vagrant box add bento/ubuntu-24.04 --box-version 20241002

# List the boxes you have
vagrant box list

# Update a box
vagrant box update
```

<Callout title="Pin the box version">
  A box tag such as `bento/ubuntu-24.04` is a moving target. Pin an exact
  `--box-version` in your Vagrantfile so every developer and CI job starts from the
  same image.
</Callout>

## Common Commands

```bash
# Global status
vagrant status

# SSH details for the connection
vagrant ssh-config

# Port forwarding
vagrant port --guest 80

# Run a command inside the machine
vagrant ssh -c "systemctl status nginx"

# Copy a file in or out
vagrant ssh -c "cat /var/log/syslog"
vagrant copy ./file.txt /tmp/file.txt

# Suspend and resume
vagrant suspend
vagrant resume
```

## Provisioning with Ansible

```ruby
Vagrant.configure("2") do |config|
  config.vm.box = "bento/ubuntu-24.04"

  # Point Vagrant at your Ansible playbooks
  config.vm.provision "ansible" do |ansible|
    ansible.playbook = "playbooks/site.yml"
    ansible.compatibility_mode = "2.0"
    ansible.extra_vars = { vagrant: true }
  end
end
```

```bash
# Re-provision an existing machine
vagrant provision --provision-with ansible
```

## Multi-Machine Environments

```ruby
Vagrant.configure("2") do |config|
  config.vm.box = "bento/ubuntu-24.04"

  config.vm.define "web" do |web|
    web.vm.hostname = "web"
    web.vm.network "private_network", ip: "192.168.56.10"
  end

  config.vm.define "db" do |db|
    db.vm.hostname = "db"
    db.vm.network "private_network", ip: "192.168.56.11"
  end
end
```

```bash
# Bring up everything
vagrant up

# Bring up one machine
vagrant up web

# Run a command on a specific machine
vagrant ssh db
```

## Choosing a Provider

```bash
# List the installed providers
vagrant provider --list

# Use a specific provider
vagrant up --provider=libvirt
```

On Linux, **libvirt/KVM** is dramatically faster than VirtualBox. On Windows, use
**Hyper-V**. On macOS, **VMware Fusion** or **UTM** are the fastest options.

## Troubleshooting

<Accordion type="single">
  <AccordionItem value="issue-1">
    <AccordionTrigger>
      The machine does not start
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # Check the provider
      vagrant provider --list

      # See the detailed error
      vagrant up --debug

      # Verify virtualization is enabled in the BIOS/UEFI
      egrep -c '(vmx|svm)' /proc/cpuinfo
      ```
      On Windows, Hyper-V must be enabled before the VirtualBox provider works.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-2">
    <AccordionTrigger>
      The box fails to download
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # Check for a proxy or firewall problem
      curl -I https://app.vagrantup.com

      # Retry, or install the box from a local file
      vagrant box add bento/ubuntu-24.04 --file ./ubuntu-24.04.box
      ```
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-3">
    <AccordionTrigger>
      Synced folders are empty or broken
    </AccordionTrigger>
    <AccordionContent>
      VirtualBox and Hyper-V both have known issues with the default shared-folder
      implementation. Switch the type explicitly in the Vagrantfile:
      ```ruby
      config.vm.synced_folder ".", "/vagrant", type: "rsync", rsync__exclude: [".git/"]
      ```
      On Windows, `type: "rsync"` also avoids the Hyper-V performance problems.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-4">
    <AccordionTrigger>
      SSH connection refused or timeouts
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # Get the exact SSH command Vagrant would use
      vagrant ssh-config

      # Connect with it directly
      vagrant ssh -c "uptime"
      ```
      A wrong forwarded port or a stale `~/.vagrant.d/insecure_private_key` causes most
      connection problems. `vagrant destroy -f && vagrant up` resets the machine.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-5">
    <AccordionTrigger>
      Provisioning fails halfway through
    </AccordionTrigger>
    <AccordionContent>
      Provisioners run in order and stop at the first failure. Run them again without
      recreating the machine:
      ```bash
      vagrant provision
      ```
      Use `vagrant up --provision` to re-run them during the next start.
    </AccordionContent>
  </AccordionItem>

  <AccordionItem value="issue-6">
    <AccordionTrigger>
      The machine is slow or runs out of disk
    </AccordionTrigger>
    <AccordionContent>
      ```bash
      # See the disk usage
      vagrant ssh -c "df -h"

      # Free space from old boxes
      vagrant box prune

      # Destroy unused machines
      vagrant list
      vagrant destroy -f
      ```
      Keep at least 20 GB free for the images and the guest disks.
    </AccordionContent>
  </AccordionItem>
</Accordion>

## Best Practices

1. **Commit the Vagrantfile** — it is the definition of the environment.
2. **Pin the box version** so every machine starts from the same image.
3. **Provision with code**, not with manual steps inside the guest.
4. **Use `vagrant destroy -f` instead of `rm -rf .vagrant`** — it cleans up properly.
5. **Never commit a `.vagrant` directory** or a `*.box` file to Git.
6. **Use `vagrant box prune`** regularly to reclaim disk space.
7. **Prefer libvirt/KVM on Linux** and Hyper-V on Windows for performance.
8. **Set the memory and CPU count explicitly** so the environment is predictable.
