Every major cloud provider ships a first-party command line client. These guides cover installing
them, authenticating safely and configuring profiles so you can work across multiple accounts
without leaking credentials.

Every guide is written against the current release line and verified against the upstream
documentation:

## What you will learn

- **AWS CLI** — install the client, configure named profiles, assume roles and enable completion.
- **Azure CLI** — install the client, sign in interactively or with a service principal and manage
  subscriptions.
- **Google Cloud CLI** — install `gcloud`, authenticate with a service account and manage projects.

## Credential hygiene

1. Prefer short-lived credentials from the cloud provider's own identity service
2. Use named profiles or service accounts per environment instead of exporting static keys
3. Never commit credentials — add `.aws/`, `.azure/` and `gcloud` config directories to `.gitignore`
4. Rotate keys on a schedule and remove unused ones
5. Audit which principal performed each change with cloud audit logs
